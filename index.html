THE PROBLEM

ทำไมอาชีพนี้จึงจำเป็น

คนส่วนใหญ่วางแผนให้เงิน “เติบโต” ได้ดี แต่ไม่ได้วางแผนให้เงิน “ไม่หายไป”: ช่องว่างนี้คือที่ที่อาชีพนี้ยืนอยู่

ฝั่งนักลงทุนรายบุคคล

อายุ 22–50+ ปี ที่ต้องการเข้าสู่ตลาดสากล

  • เปิดพอร์ตต่างประเทศได้ แต่ไม่รู้ว่าควรเริ่มตรงไหน
  • ถือคริปโตอยู่ แต่เก็บไว้บนกระดานเทรดทั้งหมด
  • สนใจ Options และ Pink Sheets โดยประเมินความเสี่ยงไม่ได้
  • สูญเงินจากความผิดพลาดที่ป้องกันได้ตั้งแต่ต้น

ฝั่งองค์กรและ SMEs

ผู้บริหารที่ยังไม่มีทีมความปลอดภัยไซเบอร์

  • ถือสินทรัพย์ดิจิทัลในนามบริษัทโดยไม่มีระบบควบคุมสิทธิ์
  • ไม่ทราบว่าระบบการเงินภายในมีช่องโหว่ตรงไหน
  • ต้องเลือกเทคโนโลยีการเงินใหม่ แต่ประเมินความคุ้มค่าไม่ได้
  • มีหน้าที่ตาม PDPA แต่ไม่มีคนดูแลจริง

SKILLS

ทักษะที่อาชีพนี้ต้องใช้

แบ่งเป็นทักษะเชิงเทคนิคที่วัดผลได้ และทักษะเชิงมนุษย์ที่ตัดสินว่าคำแนะนำจะถูกนำไปใช้จริงหรือไม่

Hard Skillsทักษะเชิงเทคนิค

  1. 1

    Digital Asset Custody: ออกแบบระบบเก็บรักษาสินทรัพย์ดิจิทัลแบบ Multi-signature และ Cold Storage รวมถึงแผนกู้คืนกุญแจ

  2. 2

    API & Cloud Security: จำกัดสิทธิ์ API key ของระบบเทรด ตรวจการตั้งค่า cloud ที่เปิดสาธารณะโดยไม่ตั้งใจ

  3. 3

    Financial Data Analysis: ใช้ Python และ Power BI วิเคราะห์ความเสี่ยงพอร์ตและทดสอบกลยุทธ์ย้อนหลัง

  4. 4

    RegTech & Compliance: เข้าใจ PDPA, KYC/AML และมาตรฐาน SOC 2 มากพอจะแปลงเป็นข้อกำหนดทางเทคนิคได้

Soft Skillsทักษะเชิงมนุษย์

  1. 1

    Risk Communication: อธิบายความเสี่ยงทางเทคนิคให้ผู้บริหารที่ไม่ใช่สายไอทีตัดสินใจได้ โดยไม่ลดทอนความถูกต้อง

  2. 2

    Ethical Judgment: ตัดสินใจเมื่อผลประโยชน์ของผู้ว่าจ้างขัดกับสิทธิของเจ้าของข้อมูล (ดูกรณีศึกษาด้านล่าง)

  3. 3

    Cross-disciplinary Collaboration: ทำงานร่วมระหว่างทีมการเงินและทีมความปลอดภัย ซึ่งใช้คนละภาษาและมีคนละเป้าหมาย

  4. 4

    Continuous Learning: ทั้งภัยคุกคามและกฎหมายเปลี่ยนทุกปี ความรู้ที่หยุดนิ่งคือความเสี่ยงในตัวมันเอง

CAREER ROADMAP

แผนที่เส้นทางอาชีพ 3 ระยะ

จากห้องเรียน ม.5 ไปจนถึงการเป็นที่ปรึกษาอิสระ, แต่ละระยะมีเป้าหมายที่วัดผลได้

  1. 01
    STAGE 1 · ระยะเตรียมตัว

    ม.5 – มหาวิทยาลัย

    สร้างฐานความรู้และพิสูจน์ด้วยผลงานจริง

    • เรียนต่อสาขา Computer Engineering หรือ Financial Technology
    • สอบใบรับรอง CompTIA Security+ เป็นใบแรก
    • ลงแข่ง Hackathon ต่อเนื่องปีละอย่างน้อย 2 รายการ
    • เข้าโครงการบ่มเพาะธุรกิจเพื่อเข้าใจฝั่งเงินทุน
    • ฝึกวิเคราะห์พอร์ตด้วย Python จากข้อมูลจริง
  2. 02
    STAGE 2 · ระยะเริ่มต้นทำงาน

    1 – 3 ปีแรก

    เข้าสู่อาชีพในฐานะผู้ปฏิบัติ ไม่ใช่ที่ปรึกษา

    • เริ่มที่ตำแหน่ง Security Analyst หรือ Fintech Analyst ในธนาคารหรือบริษัท fintech
    • สะสมงานตรวจสอบจริงให้ครบทั้งฝั่ง custody และฝั่งระบบองค์กร
    • สอบ CISSP Associate หรือ CISA
    • เรียนรู้กรอบกฎหมาย PDPA จากการทำงานจริง ไม่ใช่จากตำรา
    • สร้างเครือข่ายทั้งสายการเงินและสายความปลอดภัย
  3. 03
    STAGE 3 · ระยะเติบโตและเชี่ยวชาญ

    4 ปีขึ้นไป

    เป็นที่ปรึกษาอิสระที่รับผิดชอบผลลัพธ์ได้เต็มตัว

    • เปิดงานที่ปรึกษาอิสระ หรือตั้งบริษัทที่ปรึกษาขนาดเล็ก
    • ออกแบบระบบ custody ระดับองค์กรให้ลูกค้าโดยตรง
    • เป็นที่ปรึกษาด้าน RegTech ให้บริษัทที่กำลังระดมทุน
    • พัฒนาเครื่องมือประเมินความปลอดภัยของตัวเองเป็นผลิตภัณฑ์
    • ถ่ายทอดความรู้ต่อ ผ่านการสอนหรือเขียนเผยแพร่

ทำไมผมเลือกเส้นทางนี้

ผมมีประสบการณ์กับสายเทคโนโลยีจากการแข่งขัน Hackathon หลายรายการ ทั้ง ThEP Hackathon และ PSRU Cyber Hackathon ซึ่งทำให้ผมได้ลงมือแก้ปัญหาจริงภายใต้เวลาจำกัด และเห็นว่าเทคโนโลยีที่ดีไม่ได้จบที่โค้ดที่ทำงานได้

DIGITAL ETHICS

กรณีศึกษาจริยธรรมและพลเมืองดิจิทัล

สถานการณ์จำลองที่อาชีพนี้มีโอกาสเจอจริง พร้อมแนวทางแก้ไขตามกฎหมายไทย

สถานการณ์

ระหว่างตรวจสอบความปลอดภัยระบบการเงินให้บริษัทลูกค้าแห่งหนึ่ง ผมพบว่าฐานข้อมูลลูกค้ากว่า 12,000 รายชื่อ ซึ่งมีทั้งเลขบัญชีและเอกสารยืนยันตัวตน ถูกเข้าถึงจากภายนอกมาแล้วประมาณ 3 เดือน โดยบริษัทไม่เคยทราบมาก่อน

เมื่อผมรายงานให้ผู้บริหารที่ว่าจ้าง ผู้บริหารสั่งไม่ให้บันทึกเรื่องนี้ลงในรายงานฉบับสมบูรณ์ โดยให้เหตุผลว่าบริษัทกำลังจะปิดการระดมทุนรอบ Series A ภายในสองสัปดาห์ พร้อมเสนอค่าตอบแทนเพิ่มเป็นสองเท่า และอ้างว่าสัญญา NDA ที่เซ็นไว้ครอบคลุมเรื่องนี้อยู่แล้ว

คำถาม: ผมควรทำอย่างไร เมื่อคนที่จ่ายเงินให้ผม สั่งให้ปกปิดสิ่งที่กระทบคน 12,000 คนที่ไม่รู้ตัว

แนวทางแก้ไขตามหลักกฎหมาย

  1. หน้าที่ตามกฎหมายไม่ใช่สิ่งที่ผู้ว่าจ้างสั่งยกเลิกได้

    พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 มาตรา 37(4) กำหนดให้ผู้ควบคุมข้อมูลส่วนบุคคล ต้องแจ้งเหตุละเมิดต่อสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล ภายใน 72 ชั่วโมงนับแต่ทราบเหตุ เว้นแต่ประเมินแล้วว่าไม่มีความเสี่ยงต่อสิทธิและเสรีภาพของบุคคล และเมื่อมีความเสี่ยงสูง ต้องแจ้งเจ้าของข้อมูลพร้อมมาตรการเยียวยาโดยไม่ชักช้า ด้วย

    กรณีนี้เป็นข้อมูลบัญชีและเอกสารยืนยันตัวตน จึงเข้าข่ายความเสี่ยงสูงชัดเจน หน้าที่นี้เป็นของบริษัทในฐานะผู้ควบคุมข้อมูล ผู้บริหารจึงไม่มีอำนาจยกเว้นให้ตัวเอง

  2. ต้นทุนของการปกปิดสูงกว่าเงินที่เสนอมาก

    การไม่แจ้งเหตุตามกำหนดมีโทษปรับทางปกครองสูงสุด 3,000,000 บาท ตามมาตรา 83 หากแจ้งช้ากว่า 72 ชั่วโมงด้วยเหตุจำเป็น ยังต้องชี้แจงเหตุผลต่อสำนักงานภายใน 15 วัน การเงียบไว้เฉย ๆ จึงไม่ใช่ทางเลือกที่มีอยู่จริงในทางกฎหมาย

  3. NDA ไม่คุ้มครองการปกปิดการฝ่าฝืนกฎหมาย

    ข้อตกลงรักษาความลับมีไว้คุ้มครองความลับทางการค้า ไม่สามารถใช้เป็นเหตุให้ละเว้นหน้าที่ตามกฎหมายได้ และการรับเงินเพิ่มเพื่อแลกกับการปิดบัง อาจทำให้ผมกลายเป็นผู้มีส่วนร่วมในการกระทำผิดเสียเอง ไม่ใช่เพียงพยานที่รู้เห็น

  4. สิ่งที่ผมจะทำจริง

    ส่งรายงานฉบับสมบูรณ์เป็นลายลักษณ์อักษร ระบุสิ่งที่พบ วันเวลาที่แจ้ง และหน้าที่ตามมาตรา 37(4) พร้อมเก็บสำเนาไว้เป็นหลักฐาน · แจ้งให้บริษัททราบว่ากรอบเวลา 72 ชั่วโมงเริ่มนับแล้ว · ปฏิเสธค่าตอบแทนเพิ่มเป็นลายลักษณ์อักษร · หากบริษัทยังปฏิเสธที่จะแจ้ง ให้ยุติสัญญาและบันทึกเหตุผลไว้

  5. สิ่งที่ผมจะไม่ทำ และเหตุผล

    ผมจะไม่นำข้อมูลลูกค้าหรือหลักฐานไปเปิดเผยต่อสาธารณะหรือต่อสื่อด้วยตัวเอง เพราะผมอยู่ในฐานะผู้ประมวลผลข้อมูล การเผยแพร่เองจะเป็นการละเมิด PDPA ซ้ำ และทำให้เจ้าของข้อมูลทั้ง 12,000 รายเสียหายเพิ่มขึ้นอีกชั้น ช่องทางที่ถูกต้องคือผลักดันให้บริษัทแจ้งเอง และหากยังเพิกเฉย จึงแจ้งเบาะแสต่อสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคลโดยตรง ซึ่งเป็นหน่วยงานที่มีอำนาจตามกฎหมาย

หลักพลเมืองดิจิทัลที่ใช้: ความรับผิดชอบต่อผู้ที่ไม่มีเสียงในเหตุการณ์ (เจ้าของข้อมูล 12,000 ราย) ต้องมาก่อนความสัมพันธ์ทางธุรกิจกับผู้ว่าจ้าง และการรายงานต้องทำผ่านช่องทางที่ถูกกฎหมาย ไม่ใช่การประจาน
